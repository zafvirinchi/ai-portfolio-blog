## Why this migration mattered

We had to replace deprecated modules, revisit TLS settings, remove unsupported internal APIs, and modernize the build and runtime setup.

## Key migration challenges

- Deprecated Java EE modules were no longer available.
- Some old libraries were not compatible with Java 17.
- TLS and security defaults required validation.
- Build pipelines needed updates for the new runtime.

## What we changed

- Replaced legacy dependencies with supported alternatives
- Updated JVM and build configuration
- Validated API compatibility and performance
- Introduced modern Java features where appropriate

## Lessons learned

A Java migration is not just a code upgrade. It is a platform, dependency, security, and testing upgrade together.
